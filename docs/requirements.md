# 医療シミュレーションゲーム 要件定義（作業中）

> 本ゲームは医療教育・エンターテインメント目的のシミュレーションであり、実際の診断・治療には使用しない。

## 0. 前提条件（ユーザー決定事項）

| ID | 内容 |
|----|------|
| P-1 | 開発・プレイともにスマートフォンのみで行う |
| P-2 | 開発・プレイともに無料。従量課金のAPI（LLM API等）は使用しない |

### 前提から導かれる制約
- ゲーム実行時にクラウドAIで症例・会話・判定を生成することはできない（API費用が発生するため）。
- スマホ上でのローカルLLM実行は性能・容量面で現実的でない。
- したがって、医学的内容はすべて**ゲームに同梱する構造化データ**とルールエンジンで扱う（要件6「AIに自由生成させない」とも整合）。
- 配信方式の有力候補：ブラウザで動く静的Webアプリ（PWA）を GitHub Pages で無料公開（インストール不要、オフライン可）。※正式決定は「実装技術」の項で行う。

## 1. 決定済み仕様
初版プロンプト 4章・5章・6章・8章の内容をすべて維持する（診療科ローテーション、選択式問診、詳細身体診察、検査セット＋個別検査、プレイヤー管理の鑑別診断、実在薬剤ベースの処方、内部状態による経過・転帰、専門医連携、ゲーム風UI、MVPから段階的拡張）。

### 1-1. 症例生成方式（決定）
- **B. ルールベース自動生成**を採用する。
- 疾患ごとに「疾患モデル」（症状の出現頻度、身体所見、検査値分布、重症度別の進行、治療反応）を構造化データとして定義し、来院ごとにランダムな患者を生成する。
- 生成は医学的制約ルールに従い、病態と矛盾する組み合わせを出さない。
- データ作成は開発時にAIが行い、**人による医学的レビューは行わない**。
- 代替の品質担保：自動整合性チェック（値域・禁忌・症状と病態の対応・時間経過の妥当性）をテストとして実装し、各データに根拠（ガイドライン・添付文書等）の出典欄を持たせる。

### 1-2. ゲーム内時間の進行方式（決定）
- **C. 行動ごとに時間が進む方式を基本とし、場面に応じて切り替える**。
- 通常時：プレイヤーの各行動（問診・診察・検査・処置など）に所要時間を設定し、行動した分だけゲーム内時間が進む。操作しない間は時間が止まる（スマホでの中断に対応）。
- 経過観察・入院管理：「数時間進める」「翌日へ」などの時間スキップ操作で時間を進める。スキップ中も患者の内部状態は時間経過に応じて変化し、急変時はスキップを中断して通知する。
- 救急・急変：制限時間つきの緊迫モードとする（具体的な制限方式は画面構成・難易度の検討時に決定）。
- 検査結果は所要時間の経過後に返る。不要な検査は時間の浪費として患者の状態に影響しうる。

### 1-3. 患者の来院方式（決定）
- **C. MVPは1人ずつ、後からシフト制へ拡張**。
- MVP：1人の患者の診療が完了（転帰確定・帰宅・入院引き継ぎ等）すると次の患者が来院する。
- 拡張：外来・当直などのシフト単位で、待合室に複数患者が並び、検査待ちの間に別患者を診療できる方式を追加する。
- MVPの時点から、データ構造・時間管理は複数患者の同時進行に対応できる設計とする。
- 疾患の出現ロジック（決定）：以下の重み付けで来院疾患を抽選する。
  - 診療科ごとの疫学的頻度（common disease ほど高頻度）
  - 季節（インフルエンザ・熱中症など季節性疾患の補正）
  - プレイヤーレベル（重症・稀少症例は一定レベル以上で解放）
  - 将来拡張：疾患を指定できる練習モード

### 1-4. MVP向けの仕様（推奨案を一括承認）
| 項目 | 決定内容 |
|---|---|
| 実装技術 | 静的Webアプリ（PWA）。素のJavaScript（ES Modules）、ビルド不要。GitHub Pagesで無料公開。ホーム画面追加・オフライン対応 |
| AI利用範囲 | 開発時のデータ作成・コード作成のみ。ゲーム実行時はAIを使わない（API費用ゼロ） |
| スコア・評価 | 診断30・治療30・検査15・方針10・転帰15＝100点。S/A/B/C/D評価と振り返り画面。死亡は「不可避」と「回避可能」を区別 |
| 難易度 | MVPは1種類。将来「研修医モード（ヒントあり）」を追加 |
| キャリア | MVPは経験値とレベルのみ。レベルで疾患（Lv2: 心不全・DKA）や重症例（Lv3）が解放。昇格・診療科ローテーションは後日 |
| 画面構成 | 上部に患者情報・時刻・バイタル、下部タブ（問診／診察／検査／鑑別／治療／カルテ）。カード型UI、片手操作 |
| データ設計 | 疾患・問診・診察・検査・薬剤を構造化データ（JSモジュール）として同梱。1疾患1ファイルで追加しやすい |
| セーブ | 端末のブラウザ保存領域（localStorage）に自動保存。ログイン不要 |

### 1-5. MVPの範囲
- 診療科：内科（救急外来）
- 疾患（6）：市中肺炎、急性腎盂腎炎、急性胃腸炎（ウイルス性）、急性心不全、糖尿病性ケトアシドーシス、急性虫垂炎（外科コンサルト→手術）
- 薬剤：抗菌薬・解熱鎮痛薬・制吐薬・循環器薬・インスリン・電解質補正・昇圧薬など24種＋輸液4種＋酸素
- 機能：問診→診察→検査→鑑別→最終診断→治療・方針→入院管理（時間スキップ／自動経過）→退院後の経過→振り返り

### 1-6. 医学的整合性の担保（実装済み）
- 生理モデル：病勢(burden)・体液量・血糖・カリウム等の内部状態から、バイタル・検査値を一元的に導出（例：DKAのpH/HCO3/pCO2はHenderson-Hasselbalch式とWinter式、AGはNa−Cl−HCO3、高血糖による見かけの低Na）
- 自動テスト（`npm test`）：参照漏れ、生理学的範囲、疾患ごとの必須所見（DKA三徴、心不全のBNP上昇など）、処方安全ルール、模範診療での救命率・無治療での死亡率、状態変化の連続性、採点の妥当性
